**1. Create ConfigureFeedbackTemplateCommand + Handler** (D-02: template-driven prompts)

Command record: ConfigureFeedbackTemplateCommand(Guid CycleId, string FeedbackType, string Name, IReadOnlyList<FeedbackPromptDefinitionInput> Prompts) : ICommand<Result<Guid>>

Input record: FeedbackPromptDefinitionInput(string PromptText, string? Description, bool IsRequired, int DisplayOrder)

Handler logic:
1. Load PerformanceCycle by CycleId; fail NotFound if missing
2. Verify cycle is editable (Status == Draft); fail Forbidden if not
3. Parse FeedbackType string to CampaignWorkItemType (PeerFeedback or UpwardFeedback); fail Validation if invalid
4. Check no existing FeedbackTemplateSnapshot for this cycle + type; fail Conflict if exists
5. Create FeedbackTemplateSnapshot via factory method (per D-02, D-04)
6. Add to dbContext.FeedbackTemplateSnapshots
7. Emit GovernanceConfigured audit event (or a new FeedbackTemplateConfigured action — but since D-19 doesn't define one, use GovernanceConfigured with descriptive message)
8. SaveChanges
9. Return snapshot.Id

**2. Create SubmitFeedbackResponseCommand + Handler** (D-01, D-03, D-13, D-16, D-19)

Command record: SubmitFeedbackResponseCommand(Guid WorkItemId, IReadOnlyList<FeedbackAnswerInput> Answers, string? GeneralComment) : ICommand<Result<Guid>>

Input record: FeedbackAnswerInput(Guid PromptSnapshotId, string AnswerText)

Handler logic (following FormalReviewCommands.cs pattern):
1. Validate employee context (currentUser.EmployeeId.HasValue); fail Forbidden if not
2. Load CampaignWorkItem by WorkItemId; fail NotFound if missing
3. Validate work item type is PeerFeedback or UpwardFeedback; fail Forbidden if not
4. Validate work item AssigneeEmployeeId == currentUser.EmployeeId; fail Forbidden if not assigned
5. Validate not self-feedback: workItem.SubjectEmployeeId != currentUser.EmployeeId; fail Validation "Feedback.SelfFeedback" if same
6. Check no existing FeedbackResponseContent for this WorkItemId; fail Conflict "Feedback.AlreadySubmitted" if exists (D-01: one per work item)
7. Load FeedbackTemplateSnapshot for cycle + type; fail Conflict "Feedback.TemplateMissing" if missing
8. Validate required prompts answered (every prompt with IsRequired must have a non-empty answer); fail Validation "Feedback.MissingRequiredPrompts" if missing (D-16)
9. Create FeedbackResponseContent via factory method with answers, prompt text preservation (D-04)
10. Call content.Submit(DateTime.UtcNow) to transition Draft -> Submitted (D-13)
11. Create FeedbackIdentityMapping via factory method (D-05: separate table, ResponseContentId + WorkItemId + ReviewerEmployeeId)
12. Create FeedbackResponseVersion (version 1, initial submission, D-14)
13. Transition CampaignWorkItem: workItem.Submit(DateTime.UtcNow)
14. Emit FeedbackResponseSubmitted audit event (D-19)
15. SaveChanges (single transaction for content + mapping + version + work item + audit)
16. Return content.Id

**1. ReviseFeedbackResponseCommand + Handler** (D-13: revision while window open, D-14: append-only)

Command record: ReviseFeedbackResponseCommand(Guid ResponseContentId, IReadOnlyList<FeedbackAnswerInput> Answers, string? GeneralComment) : ICommand<Result<Guid>>

Handler logic:
1. Validate employee context
2. Load FeedbackResponseContent; fail NotFound if missing
3. Load FeedbackIdentityMapping by ResponseContentId to verify ownership (this is the ONE place identity mapping is read in a command handler — for authorization, not for display)
4. Validate mapping.ReviewerEmployeeId == currentUser.EmployeeId; fail Forbidden if not
5. Validate content.Status == Submitted (can only revise submitted responses); fail Forbidden if Draft or Locked
6. Load FeedbackTemplateSnapshot by content.TemplateSnapshotId
7. Validate required prompts answered
8. Create new FeedbackResponseVersion (increment version number, D-14 append-only)
9. Update content.Answers (replace with new answers — the latest version is active)
10. Emit FeedbackResponseSubmitted audit event (revision is a re-submission)
11. SaveChanges
12. Return content.Id

**2. WithdrawFeedbackResponseCommand + Handler** (D-13: Draft status, D-15: soft withdrawal)

Command record: WithdrawFeedbackResponseCommand(Guid ResponseContentId) : ICommand<Result>

Handler logic:
1. Validate employee context
2. Load FeedbackResponseContent; fail NotFound if missing
3. Load FeedbackIdentityMapping to verify ownership
4. Validate mapping.ReviewerEmployeeId == currentUser.EmployeeId; fail Forbidden if not
5. Validate content.Status == Submitted; fail Forbidden if Draft or Locked
6. Call content.Withdraw(DateTime.UtcNow) — transitions to Draft, sets SubmittedAt = null
7. Emit FeedbackResponseWithdrawn audit event (D-19)
8. SaveChanges
9. Return Result.Success()

**3. InvalidateFeedbackResponseCommand + Handler** (D-17: administrative invalidation)

Command record: InvalidateFeedbackResponseCommand(Guid ResponseContentId, string Reason) : ICommand<Result>

Handler logic:
1. Validate employee context
2. Validate user has cycle management permission (CanManageCycles); fail Forbidden if not
3. Load FeedbackResponseContent; fail NotFound if missing
4. Validate Reason is not null/empty; fail Validation if missing
5. Call content.Invalidate(Reason) — sets IsInvalidated = true, InvalidationReason
6. Emit FeedbackResponseInvalidated audit event (D-19)
7. SaveChanges
8. Return Result.Success()

**4. ResolveFeedbackIdentityCommand + Handler** (D-07/D-10: exceptional identity resolution)

Command record: ResolveFeedbackIdentityCommand(Guid ResponseContentId, string Reason) : ICommand<Result<FeedbackIdentityDto>>

Input DTO: FeedbackIdentityDto(Guid WorkItemId, Guid ReviewerEmployeeId)

Handler logic:

3. Load FeedbackIdentityMapping by ResponseContentId; fail NotFound if missing
4. Emit FeedbackIdentityAccessed audit event with reason (D-19)
5. SaveChanges
6. Return new FeedbackIdentityDto(mapping.WorkItemId, mapping.ReviewerEmployeeId)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Reviewer → Submit Handler | Reviewer must own the work item; self-feedback blocked |
| Reviewer → Revise Handler | Only original reviewer can revise; status must be Submitted |
| Admin → Invalidate Handler | Requires cycle management permission; mandatory reason |
| Compliance → ResolveIdentity Handler | Requires ConfidentialIdentityView permission; audit logged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | SubmitFeedbackResponse creating identity mapping | mitigate | Identity mapping created in same transaction but separate table; never exposed in normal reads |
| T-04-05 | Tampering | Self-feedback via Submit | mitigate | Explicit validation: workItem.SubjectEmployeeId != currentUser.EmployeeId |
| T-04-06 | Elevation of Privilege | ResolveFeedbackIdentity without permission | mitigate | ConfidentialIdentityView permission check via PerformanceAccessPolicyService; audit event emitted |
| T-04-07 | Tampering | Invalidation without reason | mitigate | Mandatory reason validation in InvalidateFeedbackResponseCommandHandler |
</threat_model>
