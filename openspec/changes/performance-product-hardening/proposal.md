## Why

A deep senior-level investigation of the whole Performance module (see `.local-docs/Performance/performance-product-hardening-exploration.md`) found that the live product is a genuinely meaty, demoable MVP — but it is carrying a large **Packet-A remnant surface** that survived the P1.3 cleanup: a full anonymous **Feedback** social system, an **Exception-case** workflow, a **Formal-review** engine, and a **Work-item** aggregator. That's ~4,700 lines of dead backend across features/controllers/tests/entities, **14 empty tables deployed into every tenant schema**, **three live `[Authorize]` HTTP route groups** with no frontend (including a de-anonymization endpoint the product direction explicitly forbids), and **7 dead permissions seeded into every tenant's role templates**. Worse, the dead `FormalReviewsController` is a premature evaluation engine that will collide with the future `performance-evaluation-self-manager` change. Alongside this dead weight, the just-completed progress slice has two correctness/observability gaps (a concurrency conflict that surfaces as a 500 instead of the designed retryable error; an unattributable-actor fallback), the permission system has a structural weakness that already caused a shipped token-generation 500, and several UI captions violate the documented no-explanatory-text standard (one forward-references check-ins that don't exist yet). This change removes the dead surface and closes those gaps so the module is lean, defensible, and the ground is clear for the evaluation engine. It lands in the same branch/PR as `performance-record-progress-updates`.

## What Changes

- **REMOVE the dead Packet-A backend surface**: the `Feedback`, `Exceptions`, `Reviews` (FormalReview), and `WorkItems` feature areas; their controllers (`FeedbackController`, `FormalReviewsController`, `CampaignWorkItemsController`); their entities, EF configurations, and enums; and their tests. **BREAKING** at the HTTP layer: `/api/performance/feedback/*`, `/api/performance/reviews/*`, and `/api/performance/work-items/*` cease to exist (no frontend or `@repo/api` consumer today; verified dead).
- **REMOVE the unwired `CloseCycle` command and the dead `Active`/`Closed` cycle states** (`PerformanceCycleStatus`); the lean launch path is `Draft → Launched`. Real cycle closure is designed later (umbrella change 8).
- **REMOVE the 7 dead permissions** (`ReviewSelfManage`, `ReviewTeamManage`, `FeedbackSubmit`, `ExceptionManage`, `ExceptionAction`, `ExceptionOverride`, `ExceptionAuditView`) from `PerformancePermissions`, `PerformancePermissions.All`, `CorePermissionCatalog.Definitions`, and their seedings in `AccessProfileTemplates`. Keep `ObjectiveProgressCorrect` (intentionally dormant per the progress design).
- **DROP the 14 dead tables** via one additive EF migration in the `performance` schema; regenerate the model snapshot; keep the migration gate clean.
- **HARDEN the progress write path**: catch `DbUpdateConcurrencyException` in `RecordObjectiveProgress` and return a typed **retryable conflict** carrying the fresh plan version (matching every other cycle command and the progress design's own stated contract); the employee dialog preserves input and offers retry. **Fail closed** when the acting user id is null instead of writing a `Guid.Empty` actor into immutable history.
- **ADD a permission-catalog completeness invariant** (test): every module permission key in a `*.All` set MUST have a matching `CorePermissionCatalog` definition and vice-versa — permanently closing the "new permission → tenant-provisioning 500" class of bug that already bit once.
- **FIX UI copy** on the progress surfaces: remove explainer captions/hints (`weightedNote`, `actualHint`, `evidenceHint`, `teamProgressTerms.listDescription`) per the documented no-explanatory-text standard, and remove `readOnlyNote`'s forward-reference to check-ins (not yet built). Empty-state guidance stays.
- **FIX the overview/sidebar drift**: the Performance overview (landing) hardcodes its own door list and is **out of sync with the sidebar and breadcrumb** — it omits the new `Team progress` door and drifts on door labels/order. Drive the overview doors from the same shared `sidebar-nav` source so the two can never disagree, and make the overview's door emphasis reflect operational state instead of a fixed decorative amber border. (A full role-aware operational home — the umbrella's per-role "what needs attention / next action" — is a larger effort tracked as a separate decision; see design.)
- **MAKE the demo seed declarative** (Atlas tenant): root-cause and fix (or guard) whatever produced orphaned `PerformanceCycleApproverReassignment` rows so the seed constructs a clean demo rather than repairing corrupted data (task-7.1 "cleared 3 stale garbage reassignments" smell).
- **Tidy residue**: verify `InactivitySweepJob` liveness (remove if Packet-A); mark the `/planning` and `/configuration/(platform-admin)/performance` redirect stubs as intentional; optionally map progress visuals to DS status tokens instead of raw Tailwind colours.
- **Lightweight Core contract guard** ("and more"): add a serialization-fixture round-trip test pinning Performance's local Core-workforce contract mirror (`CoreWorkforceModels.cs`) to Core's `WorkforceController` response shape, so a Core-side field reshape fails CI instead of silently deserializing nulls at runtime.

## Capabilities

### New Capabilities

- (none) — this is a hardening/cleanup change. It adds no new user-facing capability; it removes dead surface and strengthens existing behavior. The removed Packet-A code was never spec-driven, so there is no owning spec to delta for it — its removal is code/schema cleanup, except for the dead **permissions**, which are captured under `identity-access-composition` below.

### Modified Capabilities

- `performance-navigation`: the overview and sidebar are driven by one shared door source so they cannot drift (fixes the omitted `Team progress` door and label/order drift); overview door emphasis reflects operational state, not decoration.
- `identity-access-composition`: remove the 7 dead Performance permissions from the platform permission set and role-template seedings; add the invariant that every module permission key has exactly one `CorePermissionCatalog` definition (bidirectional, enforced by test).
- `performance-objective-progress`: add a retryable-conflict requirement (concurrent progress writes on one plan return a typed retryable conflict, never a 500) and a fail-closed-actor requirement (a progress row is never written with an empty/unknown actor); apply the product's no-explanatory-text copy discipline to the progress surface.
- `performance-team-progress`: apply the no-explanatory-text copy discipline; the read-only nature is conveyed by structure, and copy must not forward-reference capabilities that are not yet built (check-ins).

## Impact

- **Backend (Performance :5401)**: delete 4 feature areas, 3 controllers, ~14 entities + configs + enums, `CloseCycle`; remove `DbSet`s; one additive drop migration; regenerated snapshot; new `try/catch` + typed conflict in `RecordObjectiveProgress`; fail-closed actor guard; contract-fixture test. Backend test count **drops** as dead tests are removed — expected.
- **SharedKernel**: remove 7 permission constants from `PerformancePermissions`/`.All` and `CorePermissionCatalog.Definitions`; add the completeness invariant test.
- **Identity (:5101)**: remove dead-permission seedings from `AccessProfileTemplates`; existing tenants hold inert grants (no endpoint serves them) — note in provisioning.
- **Frontend (`Frontend/apps/performance`)**: copy edits in `progress-terms.ts`; dialog retry-on-conflict handling; optional DS-token mapping in `progress-visuals.tsx`. `@repo/auth` `roles.ts` unaffected (team-progress permission stays).
- **Contracts/APIs**: three Performance route groups removed from the gateway surface. No change to Core, Training, or Interview modules. Core HR remains the untouched source of truth.
- **Tenancy/permissions**: fail-closed on null actor tightens the audit trail; dead-permission removal shrinks every tenant's granted surface; the invariant test protects tenant provisioning.
- **Non-goals (deferred, with reasons in the exploration)**: migration baseline squash (orthogonal, risky to bundle); My-objectives page monolith split (nice-to-have); building any evaluation/check-in/closure capability (future umbrella changes); reintroducing any removed Packet-A behavior.
