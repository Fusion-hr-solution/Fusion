Decide product, architecture and HRIS-model questions yourself (where things live, who sees what, layering, permissions, save models), reasoning from research on real HRIS/SaaS practice and design first principles. Ask the user only when the call is genuinely taste and no answer is "correct". Don't walk them through decisions one by one in chat: publish an interactive artifact (explorer: pick an actor/state, see the result, each decision with its reason, a way to agree or object) so they can check whether they're on board.

**Why:** 2026-10-17 (praise on Overview vs home) the user said they "truly don't know" and want things thought out from first principles. 2026-10-23 (B-071 settings) they repeated it firmly: "most decisions … to be made by you … I'm not too familiar with HRISs" and asked for an artifact to check out and interact with, like the B-068 catalogue and B-069 surface explorer.

**How to apply:** research → decide → record the calls with reasons in the brief/plan → publish an explorer artifact → read the verdict. Precedents: B-068 catalogue (`plans/B-068-feature-catalogue.html`, db choices), B-069 surface explorer (`plans/B-069-surface-architecture.html`).
