Extensive audit of the whole Workforce Import experience saved at `.local-docs/Core/workforce-import-experience-audit-2026-08-27.md` (evidence screenshots in `.local-docs/Core/workforce-import-audit-assets/`). Done live against tenant `solarasystems` (`admin@solarasystems.com`) with `Solara-Systems-workforce-demo.xlsx` (150 rows) over the `fresh-tenant-organization-ai-showcase` structure.

**Verdict:** functionally correct but cognitively incoherent — user can't tell "what's wrong / what do I do." Root cause: the workforce file names orgs in its own vocabulary (`SOLARA/TECH/ENG/PLATFORM`) that don't match the canonical structure (`Asteria Group / …`), so all 150 rows block on OrganizationUnresolved and the product never frames that as the one root problem.

**Ranked findings:** F1 three inconsistent loading treatments — workforce lacks a `processing` block so the shared polished `ImportProcessing` card never plays (org has it); session adds a third bespoke `UnderstandingState` (the user-flagged consolidation item). F2 mapping step is non-deterministic (shown only when AI leaves columns unresolved → "sometimes I map, sometimes not"). F3 review opens as a "150 needs attention / 0 new" alert wall with no root-cause framing (spec §4/§19 violated). F4 blockers are LAYERED (resolve org → temporal blocker appears on same row) so `needsAttentionCount` never drops = no sense of progress. F5 org resolution gives no suggestions when naming diverges (relevance heuristic scores 0) → 26 blind manual searches, no AI assist for org mapping, no dedicated reconcile surface. F6 temporal blocker falls through to `GenericBlocker` (Exclude-only) contradicting footer's batch "Establish as of baseline"; footer band is current-page-dependent. F7 no Source details/Replace/Discard inside session (spec §33/§35A) = trapped. F8 on-ramp (`PageContainer`) vs session (`ImportShell`) are two frames for one task. F9 heavy 4-step stepper (spec §2 says don't), `Details` breadcrumb leak, entry dead space, manager "Also being adde…" truncation. F10 demo data misaligned + spec §48's aligned `asteria-workforce.xlsx` doesn't exist.

**Aligned-file addendum (same day):** re-ran with `asteria-workforce-ai-demo-150.xlsx` (org names matching Asteria structure) → flow is GENUINELY GOOD: auto-mapped columns, one honest date-format decision, review opens `93 new / 57 attention / 15 grouped decisions`, org inspector shows real Suggested matches + "'Operations' appears on 10 employees", resolving a group visibly moves counts (57→49, 93→101). So the 150/0 catastrophe was org-vocabulary mismatch meeting a product that doesn't degrade gracefully. F3/F5 residue still valid (frame root cause + assist misaligned case); F1/F2/F6/F7/F8/F9 are file-independent and stand. Priority reweighted: #1 root-cause framing, #2 assisted org reconciliation, #4 loader consolidation (shows on every run).
