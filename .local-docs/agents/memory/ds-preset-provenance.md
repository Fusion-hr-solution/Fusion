`@repo/ds` was scaffolded from a shadcn **create** preset (URL preset code `b6GMQMg3l`, style `radix-nova`). Decoded against the live shadcn create bundle, the preset = **base color `zinc` + `yellow` theme (primary) + `amber` chartColor + lucide + Inter**. NOTE: `packages/ds/components.json` declares `baseColor: "neutral"` but the actual tokens are **zinc** (fg `oklch(0.141 0.005 285.823)`, hue 286 tint) — the manifest field is stale/inaccurate (harmless at runtime since `cssVariables:true` reads `src/styles/tokens.css`, but misleads a future `shadcn add`).

**Tokens were REALIGNED to the preset default 2026-09-01 (committed on `refactor/temp-branch`):** accent→neutral gray (was brand yellow; menu/selection hovers now gray), background→white (dropped off-white canvas + the redundant performance `globals.css` override), border/input→`0.92`, and radius→preset **"Medium" = `--radius: 0.625rem`**. Create-tool RADII map: none `0` / small `0.45rem` / medium `0.625rem` / large `0.875rem`. Our components use `rounded-xl` for controls + `rounded-2xl` for containers (one tier above stock radix-nova's `rounded-lg`/`rounded-xl`), so faithfulness was achieved by remapping the SCALE, not the components: `--radius-xl: 0.625rem` (controls = 10px), `--radius-2xl: 0.875rem` (containers = 14px). Earlier `--radius-xl: 0.875rem` made controls near-pill on `h-8` buttons — corrected. Fusion-ADDITIVE tokens KEPT (preset has no equivalent; DESIGN.md requires them): state families `success/warning/info(+-subtle)`, elevation `shadow-raised/overlay`, motion `duration-*`/`ease-*`, typography `type-*`, fonts. `type-*` used 456×/48 files, state colors 91×/36 files — stripping them was rejected as lossy (no green/blue in the preset) + DESIGN.md-breaking.

**Component faithfulness — DECIDED: keep ours as-is (no port).** The `/r/styles/radix-nova/<name>.json` endpoint serves the create-**preview** variant, which depends on a `cn-*` component-CSS layer (`cn-menu-translucent`, `cn-dropdown-menu-content`, `cn-rtl-flip`, `cn-font-heading`, …) and imports a preview-only `icon-placeholder`. That `cn-*` layer is NOT in any installable registry item — the radix-nova `registry:style` (`style.json`/`index.json`) has empty `cssVars` and a css block of just `@import tw-animate-css; @import shadcn/tailwind.css; @layer base`, and declares `lucide-react`+`radix-ui`+plain-Tailwind deps. So the real installed radix-nova components use plain Tailwind + lucide — exactly what our DS already does. The "11 drifted components" reading was an artifact of diffing against the preview build; vendoring the `cn-*` layer would mean scraping preview-only CSS from minified JS (fragile, opaque, anti-DS-principles) and would NOT match what `shadcn add` installs. Our 45 simple components are byte/format-faithful; the menu/overlay ones are faithful in approach. 4 legacy not-in-radix-nova (`form, toast, toaster, use-toast` — old toast lineage coexisting with `sonner`; minor debt, deletable when unused).

**Two accidental DS regressions found + fixed this session** (both "missing what upstream has"): `button-group.tsx` ButtonGroupText was missing `data-slot="button-group-text"` (broke input corner-rounding merge) → fixed, now faithful; `select.tsx` SelectContent Viewport was missing `p-1` (menu items flush to popover edge) → fixed.

**Integration seam is clean:** single shared `@repo/ds`; all three apps (core/platform/performance) import `tokens.css` identically (`tailwindcss` + `shadcn/tailwind.css` + `tw-animate-css` + `../../../../packages/ds/src/styles/tokens.css` + `@source` ds+auth). Only performance scopes one documented `--background` override. No `@repo/ui` bleed, no per-app token redefinition, no duplicate DS.
